📍 CAMERA GPS LOCATION
Off - lat/long above can be entered manually.
Turn this on from whichever device is physically at the camera (e.g. a phone at the gate, or a laptop in a ground-control vehicle for a drone). The browser's own GPS then keeps latitude/longitude - and every alert/SMS map link - updated in real time, instead of you typing coordinates in by hand.
SMS is sent via Twilio. Without TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, and TWILIO_FROM_NUMBER set as environment variables on the server, alerts are logged here but not actually texted (safe to leave unset for a demo).
Register officials with their locality (e.g. "Tambaram", "Vandalur") - type a known locality and its GPS is filled in automatically, or enter latitude/longitude yourself for an exact duty-post location. When crowd is detected, the SMS goes to the nearest official (🥇 PRIORITY 1) plus one backup (🥈 PRIORITY 2) - not everyone. Leave location and latitude/longitude blank to still register someone (and text them) without a priority rank. Add as many officials as you need - 50+ is fine.
🔑 Each official can have their OWN login for the mobile app (acknowledge alerts, report incidents, press SOS) instead of everyone sharing one admin-issued token - so the activity log below can name the specific officer, the same way it already names individual admin/viewer accounts. Click 🔑 next to an official to set or reset their username/password.
📅 SHIFT / DUTY ROSTER
Schedule which official covers which zone/gate and when. A shift can repeat every day or run on one specific weekday, and an end time earlier than the start time (e.g. 22:00 → 06:00) is treated as an overnight shift. When crowd risk needs a dispatch, whoever's roster currently has them covering that exact gate is recommended first (🟢 ON ROSTER) - ahead of anyone who's merely standing closer at that moment - via GET /api/officials/nearest. This never overrides an officer's own on/off-duty toggle, it just adds a schedule on top of it.
